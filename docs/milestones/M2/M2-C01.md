## Source and authority

[`internal/requestctx`](../../../internal/requestctx/context.go) is a root
Go 1.27.2 module with standard-library imports only. The pre-existing research
modules and their engine/dependency graphs are unchanged and are excluded by
their own nested go.mod files. There is no program, listener, TLS adapter, key
loader, engine call, allow verdict, backend address or backend call in this slice.

`Peer` has private state and **no production constructor**. Its zero value rejects.
Only package-local synthetic tests populate that state. A future separately
reviewed adapter must construct identity from verified TLS and cannot treat a
header/boolean as authentication. Nothing here proves a real peer was verified.

`NewSnapshot` validates and copies one generation and bounded public route,
peer-name and policy-pin bindings. These types are not a public configuration
schema. A token is neither a hash nor proof that two services agree. The future
operator/pairing lifecycle owns uniqueness across starts/changes/rollback; this
process-local component cannot enforce history it does not possess.

`Snapshot.Record` validates a supplied parsed request against that immutable
binding, copies it into a bounded `Recorder`, and returns an error or success of
**context recording only**. Neither result is a traffic inspection decision.
The recorder is a concrete memory consumer, without user callbacks or I/O.
Caller mutations and returned projections cannot alter retained configuration,
fields or body. Strings are cloned too, so short slices cannot retain oversized
caller backing allocations. Callers must not mutate inputs during recording.

## Bounds, fidelity and lifetime

Keep 1–8 unique routes, 1–8 unique canonical peer DNS names per route, 32-byte hex
generation, 64-byte hex opaque policy pin and an 8192-byte retained-text budget.
The text budget is not a serialized-configuration or measured heap/RSS claim.
Request limits are 64 parsed fields, 128-byte field names, 2048-byte encoded
target, 4096-byte body, a 4096-byte serialized **parsed public view**, 1024-byte
context field budget and 5120-byte combined view. Existing tighter per-field
bounds can dominate a combined ceiling; all are rejection bounds, not capacity
or performance qualification. This first component accepts ASCII header values
(including horizontal tab), not a general HTTP character-set support claim.

The original Host, encoded path/repeated slashes/query order and multiplicity,
public header names/order/duplicate values and payload are retained byte for
byte. Reserved metadata is projected separately and removed from public fields.
Only comparison folds Host ASCII case; neither authority nor target is rewritten.
Methods, media, lengths and visible parsed unsupported fields follow M2-H1/1.
Client identity remains a trusted frontend assertion, not an independently
observed public connection. Body completeness is a future adapter obligation;
matching a supplied Content-Length and byte slice does not prove original EOF.

At most four recording calls enter each snapshot concurrently; a fifth returns
capacity without an application queue. Its concrete recorder retains at most
four contexts with no eviction. Short mutex sections perform bounded computation
and copying only. Cancellation is checked before and at publication. `Retire`
serializes with publication: an already serialized record may complete first,
but no subsequent recording succeeds after retirement returns. Existing records
remain inert historical data, not a surviving generation lease. This is not the
future shared cross-generation/application/connection resource controller.

The [exact HAProxy normalization caveat](FRONTEND-INSPECTOR-CONTRACT.md) is unchanged.
Rejecting duplicate/unsupported **supplied parsed fields** cannot recover fields
already normalized away upstream. Tests explicitly demonstrate that limitation.
There is no original-wire parser or strict raw-admission claim here.

## Portable checks and remaining work

`make verify` retains all foundation checks and adds root-module formatting,
vet and ordinary tests. `make contract-race contract-fuzz` adds race checks and
ten-second/two-worker parsed-context fuzzing. Use the existing checksum-pinned
development toolchain (`make research-tools` when absent); this slice changes no
pin and downloads/installs nothing during verification. The contract wrapper
disables ambient Go environment/workspaces, module downloads and toolchain updates.
All caches stay inside this clone's ignored .tools directory.

Tests use finite synthetic parsed data and deterministic held-consumer lifecycle
barriers. They cover wrong/missing/duplicate metadata, peer/route/generation and
SNI/Host/port binding, supported methods/media, reachable exact/cap+1 bounds,
detached mutable slices and oversized string backing, byte fidelity, concurrent
capacity, cancellation, retirement and fresh-generation rejection. The external
API test cannot create an authenticated peer. No fixture starts a listener,
generates/reads a certificate, calls an engine/backend or executes natively.
Exact candidate counts/commands/results belong in the PR receipts.

Next is a **separately scoped adapter design**, including real mTLS peer
construction, paired snapshots, strict-framing resolution, complete inspection
ownership and mandatory backend admission. Vectivium still rejects required WAF;
no renderer feature or h2/gRPC/streaming profile is enabled. The M1 reload failure,
parser/CRS/advisory/resource/native gates and validation pause remain unchanged.
Rollback reverts this inert source component; no runtime state or migration exists.
