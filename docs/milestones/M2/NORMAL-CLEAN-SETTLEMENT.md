# Normal inspector termination and durable settlement

Source only, under the already approved ADR0014 normal-clean semantics. Native
qualification and Draft126's validation pause remain. Both default and explicit
source supervisor entries refuse77 before signal setup, storage or launch, using
an immutable false gate. No flag, config, receipt or callback can enable it.

The same private native owner that captures the actual fork and exclusively
waits for that exact child now has one zero-input settlement call. It requires
its own matching terminal status (or actual negative-fork NoChild), successful
once-only closure of every locally owned construction/channel handle and no
lost/ambiguous physical ownership. Controller views, ACK, Stop, supplied PIDs,
empty slots, hashes or parsed checkpoint data cannot create these private facts.
Operational use still requires qualified no-descendant/no-export construction.

Only then does its one fixed private storage bridge run. It retains the original
checkpoint descriptor and uninterrupted EX lock, saved original device/inode and
canonical committed U128. Re-traverse the fixed protected namespace, revalidate
current opened/named metadata and original inode, read exact U(g) and compare
with privately retained committed bytes; revalidate again before writing. Encode
C(g) with the SAME watermark, one exact128-byte write, one fsync, one exact readback,
then original-inode/named metadata checks and once-close of the new directory.
Keep the checkpoint/exclusion until S exits. No create, rename, truncate,
checkpoint reopen, reset, unlock, generation advance or repair is added.

All storage work follows actual terminal wait and local closure. It cannot delay
active stop/escalation/wait. Late but physically proved cleanup may settle C(g),
while missed/unverifiable timing, clock/control faults and failed service status
remain failures. C is neither a four-second pass, S-exit receipt, Ready nor an
allow verdict. An uncertain write/sync/readback/inode/close never reports known
clean and is not retried; C may have reached storage after a failed operation.

The approved [required security-record source](SECURITY-RECORDS.md) now uses this
same guard and retained EX: its terminal-boundary record and any oldest sealed
segment rotation must commit before the C write. A record failure refuses normal
settlement. Neither segment contents nor successful rotation can create the
physical facts required to reach this path.

This closes the source history step needed after normal known retirement. It
does not automatically restart or prepare the next pair: the next launch still
needs genuinely fresh paired generation g+1 and its real intent/snapshot handoff.
The maximum generation cannot wrap. Supervisor-loss cleanup/cold recovery remains
unselected; free flock, operator assertion, assumed reboot or PID adoption does
not repair U. Stopped-service maintenance is unchanged; hot updates unsupported.

## Normal generation-only successor preparation source

The same existing root frontend-owner executable now accepts the exact source
command `prepare-successor`. Its immutable native qualification gate is false
before all effects. This is ordinary configuration-data preparation after normal
clean settlement, not an image reset, U repair, new identity issuer, automatic
restart or effective policy activation. It is partial source delivery for
#23/#31/#32. No new persistent actor, endpoint or protocol is introduced.

The private preparer acquires the existing frontend writer EX and inspector's
stable checkpoint EX. It requires explicit canonical frontend C(g), matching
consumed DATA tuple/inventory and inspector C(g), plus old descriptor/intent
agreement and qualified continuous namespace/history provenance. C parsing and
a free lock alone prove no physical cleanup. The original owners' terminal and
once-close writers establish that provenance only under the still-unqualified
native no-descendant/no-export, filesystem and loader profile. It never repairs
initial-zero, U, malformed, missing or uncertain histories.

Only the bundled profile is supported. Fixed protected `/aegvium.next`0700
contains exactly `pair.snapshot` and `backend.conf`, root:wheel0400. The operator
supplies the complete immutable canonical AGPAIR2/M2-H1/3 g+1 descriptor and
AGBACK1 backend binding. The descriptor must be byte-identical to the installed
one except its exact next128-bit generation, with no wrap or same-g replay. The
backend must be byte-identical except the existing generation/full-pair-digest
binding. No roles, keys, anchors, route/policy, network endpoint, public listener,
executable, account or identity changes are accepted. There is no input argument,
path selector, credential generation or supported external-pair updater.

The actual current inspector/backend fixed role inventory, permissions, positive
common inspector GID, DER pins and exact bytes/inodes are retained and rechecked.
The existing frontend role/key/anchor material is likewise guarded without parsing
private keys; its fixed frontend configuration is recompiled. Those files carry
no generation field themselves. I continues to obtain the complete descriptor
from S's committed inherited bootstrap and parse `backend.conf` against its exact
generation/digest before preparing TLS/serving; unchanged role material still must
pass the actual loader's validity checks. The preparer grants none of those facts.

Under both uninterrupted locks, one exact existing `launch.intent` write first
places32 zeroes+LF. Both launch paths refuse that value: S requires exact g+1
under its retained checkpoint EX, and the frontend now checks matching nonzero
intent before generation consumption and again immediately before child birth.
The invalidation's file sync, exact readback, current named/inode/metadata checks,
parent-directory sync and second readback must all succeed before **any** target
replacement. Uncertain invalidation leaves every replacement untouched. No
caller failure triggers a retry, rollback or disposal.

Then four existing files are replaced by exact same-size writes only:
`/var/db/aegvium/pair.snapshot`, `/etc/aegvium/frontend/pair.agpair`,
`/etc/aegvium/inspector/backend.conf`, and `/etc/aegvium/frontend/frontend.cfg`.
Each uses one direct pinned `unix.Pwrite` and `unix.Fsync` per boundary; no Go
WriteAt/Sync short-write/EINTR continuation is used in this new transaction.
Each preserves regular-file type, owner/group/mode, nlink1, device/inode and size;
each gets exact readback, file/parent sync and current identity checks. There is
no creation, rename, truncation or state-file rewrite. Unchanged materials and
both clean histories are rechecked between writes, then every replacement is
reopened/read back and its owned write handle closed before final preparation
commit. Only then can the existing intent become exact g+1+LF. That final intent
means a completely prepared candidate, never Ready or effective security activation.

Any partial/uncertain step retains process-owned handles/locks and reports failure,
without retry or repair. A final-write uncertainty can leave a fully prepared
candidate despite the failed reply; it does not authorize another preparer run.
Later launch still independently needs the entire qualified provenance, current
matching intent/descriptor/config/material invariant and fresh generation. Locks
are advisory, root writers must cooperate, and the actual fail-closed crash/
filesystem ordering is unqualified. No local hash detects rollback or cloning.

`launch.state`, frontend lifetime C, consumed history and `security.records` are
never written by this preparer. Required U security records still must commit in
S before any new child, and C only after true cleanup. This is not complete
durable administrative-event coverage; that native acceptance gap remains held.
The bundled rc `restart` source now connects shared stop and guarded successor
preparation as described below; reload and external-profile restart refuse. This
source choreography does not prove the shared whole-appliance four-second budget.
Source preparation also retains its existing bounded startup window; it is not
shutdown qualification. Actual staging, locks/sync, credentials, services and
native failure/crash tests have not run.


## Shared stop and rc restart source

Partial source under #23/#31/#32 now wires the actual fixed rc sequence:
`service stop-all` → `frontend-owner prepare-successor-before <T0>` → existing
rc start. The first command outputs only canonical kernel monotonic milliseconds
after known submission/half-close/close of each selected one-way root stream. It
reads no reply and issues no stop/cleanup success. rc stop remains pending. A failed
submission, output write or uncertain close prevents automatic successor/start.
The source sequence accepts bundled mode only, not an assumed external frontend.

Owners retain the earliest stop origin. The C controller's private stop-at bridge
samples current time normally, then applies the older root epoch without treating
it as a clock rewind. The unchanged ACK-before100ms, drain-before3s and completion-
before4s decisions include notification time. Future/overflow origins refuse.
Frontend retirement keeps polling its same bounded endpoint, so an earlier epoch
accepted after retirement begins still shortens the existing deadline. It never
renews that deadline. Endpoint failure stays sticky without discarding the sole
original-child wait/cleanup authority.
After a missed target, timing failure stays sticky while the original owner may
still reap its actual child and close its actual descriptors. It does not guess
a PID or lose physical wait authority solely because time expired. Identity loss
still seals all future signal/wait rights. Late physical C is not a timing pass.

The before command conservatively maps T0+4s into its process-local monotonic clock.
It may retry **only** known EWOULDBLOCK/EAGAIN non-acquisition from the two existing
exclusive locks, without resetting that cutoff. An acquired-but-unclean U or any
other error is a once-only failure; it never loops a failed constructor, mutation,
close or recovery. Both native-qualified protected C histories must be joined
before that cutoff. Parsed C plus lock availability alone remain insufficient;
the actual provenance/no-descendant/no-export and terminal-provider profile is
still mandatory and unqualified.

Only after that trusted clean join does configuration preparation receive its
separate existing four-second window. New-generation startup retains its bounded
startup polling. Those are separate stages, not extra shutdown grace for either
old child. All required U-before-child and terminal C security records remain in
their existing owners. Neither deadline data, late C, a successful prep return nor
owner-running status supplies effective WAF readiness or a timing qualification.
The immutable native gates remain false. Pure/intercepted checks exercise policy
data and intercepted boundaries; they do not use the native clock or lock provider.
No product service, socket, signal, wait, lock, credential, staging or native syscall
campaign ran for these checks.
