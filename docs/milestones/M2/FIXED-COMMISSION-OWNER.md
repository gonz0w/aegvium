# Fixed first-image source composition

This is source-only under the approved offline fresh-image direction. Neither
the coordinator nor placement helper has been executed or qualified. The default
builder entry refuses; there is no force flag or serialized freshness receipt.

`tools/commission-owner.py` owns a freshly created private directory and raw target,
then the one fixed no-NIC/no-reboot installer child and all retained input/target
descriptors. Source originates from an actual signed local Git export, compiler
outputs from the pinned local tool, and stock ISO authentication using the
existing release-verification policy. This is candidate build
lineage, not release authenticity, production admission or execution permission.
There is no new signing key/publisher, imported image, SSH, snapshot or generic
BootWeave writer. The actual missing `cmd/aegvium-inspector` build fails before
target creation; it is never replaced by a dummy image or a supplied hash factory.

The fixed local build derives installer media containing the Aeg-only `install.site`
and source-built OpenBSD placement helper. The stock pre-first-boot hook executes
that helper against the mounted target. It authenticates payload consistency under
the owning build/media chain and writes only the five existing runtime file names
through exclusive creation. It performs file hash readback, ownership/mode checks,
file fsync and directory fsync, then reports the exact observed generation and
descriptor/payload digests through the actual owned VM console. This observation
alone creates no image lifetime or launch authority. On any partial state/fault,
normal handoff is forbidden; existing/user data is never repaired or deleted.

The source coordinator retains the actual O_EXCL target FD and gives QEMU an
inherited fdset reference. Exclusive terminal wait, owned channel closure,
matching target identity and successful local input-handle closure precede its
local prepared-candidate result. It retains the actual FD and exact paired
snapshot; there is no completed frontend-owner handoff or production admission.
It never starts the installed target. Root/template handlers must not replace
that owner with a path/hash/Boolean/callback or reconstruct it from observations.

Builder execution remains held: its source builds, media construction, installer/target
creation, disabled-root installation settings, placement, child signals and handoff
need an exact future qualification/effects packet. The installed/default helper
returns77. The source tag is not operational approval. The fixed candidate uses
the retained stock 8GiB/twoCPU/2GiB installer shape as an unqualified fixture, not
an accepted WAF capacity. No credentials are generated; the stock-recognized
disabled password marker is used and no SSH/NIC is configured.

Remaining native/input obligations include actual operational inspector and role
materials, exact compiler/cache and source-export closure, derived media boot/set
selection, fdset access/identity and no-export behavior, payload/header/filesystem
failure controls, all synchronization/durability, no first boot, exclusive wait/
FD reclamation and the still-missing actual frontend-owner handoff. QEMU embedded
help documents
`-no-reboot` as exit instead of rebooting; that is not observed behavior. Actual
loader/firmware/runtime closure remains unqualified. No positive installed
profile, inspector activation, recovery, deployment or four-second proof follows.
