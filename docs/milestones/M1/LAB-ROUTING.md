# Configurable lab routing and upstream TLS

Status: bounded owned-lab research authorized by the maintainer's request to accelerate the working companion. Existing #15 owns this combined outcome. Product configuration, ADR adoption and installation remain separate review gates.

LR-01 (PRD, WAF-01/03/06): replace the CLI's single hard-coded backend with a small, versioned lab JSON allowlist. Serve two synthetic .test authorities, preserve exact admitted bodies and forward only to the matching fixed loopback target. Unknown authority defaults to 421. Provide an explicit check mode; invalid input exits before any data/health bind. No dynamic discovery, DNS backend lookup, config API or hot reload.

LR-02 (EDD): configuration is lab instrumentation, not the appliance or BootWeave schema. Require canonical known JSON fields, no duplicate keys/trailing JSON, version 1, 1–8 unique lowercase .test names and <=8192 input bytes. Backend URLs allow only http/https with numeric 127.0.0.1 and nonprivileged ports, no userinfo/path/query/fragment or collision with the fixed lab data/health/ingress endpoints. HTTPS requires an explicit .test verification name and bounded regular public CA PEM file; HTTP rejects nonempty TLS fields. Build route transports and pinned CRS before listener binding; no ambient proxy/root pool, no TLS verification bypass or retries. Server-side SNI/Host binding and local sender authentication remain unqualified. Route lookup accepts only configured authority and that authority with the fixed ingress port. All routes use identical enforcement/body/response limits and close-only HTTP/1.1 policy. Keep readiness/lifecycle behavior and clean all transports/WAF state after drain.

Exact route/backend counts, bytes, generic failure responses, config/program/source hashes, nonroot execution and all process/listener/socket/TLS asset/VM cleanup are independent admission gates. Cross-built native execution remains separate from native source compilation.
