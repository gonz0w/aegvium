# Transactional lab route reload

Status: explicitly authorized bounded lab capability under existing #15. Product configuration/rules distribution and architecture adoption remain separate gates.

RL-01 (PRD, WAF-03/06): the actual nonroot CLI reloads the same owned route-config file on SIGHUP. Prepare the complete new allowlist, explicit upstream trust, transports and pinned CRS before activation. Invalid config/CA/rules preparation keeps the previous generation active. Activate the complete new route set together without rebinding data/health listeners; support known-good rollback through the same operation. This does not add rule file updates or a product management API.

RL-02 (EDD): one route-generation owner wraps the existing handler. Each request holds a read lease for its entire inspection/proxy lifetime. Prepare a replacement outside the lease lock; take the write lease to swap only after old requests drain. Release new traffic against the new handler, then close all retired transports/WAF state. Readiness retains its prior meaning while a valid old generation remains active. Reload and shutdown share ownership: shutdown closes listeners/drains servers before retiring the active generation; a prepared replacement arriving after shutdown is rejected and disposed. The CLI serializes signals; report only generic accepted/rejected/cleanup failure messages. A retirement cleanup error terminates the lab process rather than claiming rejection after an activation. Retain existing connection/body/response/deadline guards; no instant in-flight revocation, retry or unbounded streaming claim.

RL-03 (Test Design): host known-good dispatch, preparation rejection, whole-map activation/removal/rollback, held old-request drain before retirement, closed-owner rejection and cleanup. Native actual CLI: atomically replace its owned config, signal SIGHUP, observe bounded generic completion acknowledgements, assert invalid version/duplicate host/missing CA preserve old routes, activate an alternate .test authority and remove the previous authority, verify exact backend authority/body/metadata and attack denial, restore the original map and continue forwarding. Require unchanged data/health listener identity and ready health throughout successful/failed reloads, actual process identity, source/program hashes and all existing 28 path plus 163 ordinary cases. New native reload cases are separate semantic rows; preserve earlier evidence. Host drain coordination is distinct from native in-flight/load acceptance.

RL-04 (compatibility/rollback): owned lab files, .test names, loopback peers and SIGHUP only. No installed service/public listener/live app/PF change/new dependency/BootWeave schema. Rules stay embedded and pinned; same-generation compilation is not authenticated rules-update recovery. Reload waits for bounded existing handlers rather than cancelling their effects. Remove the generation wrapper/SIGHUP handling to restore startup-only config while retaining receipts. Frontend authority, sender containment, native Caddy parity, general concurrency/resources, rule distribution and appliance acceptance remain open.
