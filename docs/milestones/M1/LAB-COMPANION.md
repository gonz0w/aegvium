## Server supervision follow-up

SV-01 (PRD, WAF-03/06, #15): the owned lab process must notice termination of either HTTP Serve loop and leave its signal-wait loop to shut down. Currently Serve results are only consumed by Close, and the CLI waits for TERM/INT/HUP; a server can stop without waking that owner. Treat any Serve completion recorded before requested shutdown as a fatal lifecycle event, including nil or ordinary closed-server errors. This is bounded laboratory reliability work, not product/service adoption or a diagnosis of the earlier native reload response failure.

SV-02 (EDD): wrap the existing Serve calls, retain their exact result in the existing single-consumer shutdown receipt, and independently broadcast a payload-free failure notification. Recording an exit and beginning Close share a mutex: an exit recorded first sets readiness false and closes the notification once; Close recorded first suppresses failure notification from subsequent expected completions. Never restore readiness, consume shutdown receipts from a second observer, add a listener/probe/restart/retry, or emit raw errors. The CLI observes the broadcast alongside existing signals, calls the existing owned shutdown once and exits nonzero on failure or cleanup error. Its control loop is extracted behind a narrow fakeable interface; OpenBSD/nonroot/environment guards and actual startup stay in main.

SV-03 (Test Design): no-network library tests use fake Serve results, fake listeners, empty HTTP servers and counting closers. Verify readiness drops before notification, exact original completion remains available to shutdown, data/health-sized concurrent exits broadcast once, expected shutdown produces no failure event, and concurrent close/result publication is race-free. CLI tests use fake runtime/config callbacks and signal channels: ready/fault/stop, accepted/rejected reload, stop priority over queued HUP, failure during config read or reload, retirement/cleanup errors, generic output and one Close. Run focused functional/race tests, vet, cross-compilation, verified offline export and make verify. Preserve the SD lifecycle tests and original 163-case native admission separately.

SV-04 (compatibility and limits): notification records Go observer order, not kernel exit time or causal attribution when shutdown races a server exit. An already executing reload may finish before shutdown takes ownership; this does not add cancellation or atomic in-flight revocation. Already accepted connections/handlers may drain under existing guards; readiness false is not an instantaneous relayd table/network witness. Library owners must observe Failed or explicitly Close; notification alone does not retire resources. Failed drain/missing join retains SD's conservative engine ownership. No new CLI option, dependency, traffic policy, signal meaning, installer, live service/network or deployment. Rollback restores signal-only CLI waiting and raw Serve receipt publication, retaining evidence. Native SV/SD lifecycle tests plus the complete unchanged profile remain required before qualification; affected native/security validation stays paused under the reported access notice.
