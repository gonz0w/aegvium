# ADR-0004: execute a configured Caddy comparison

Status: bounded M1 research decision for review; no appliance adoption.
Date: 2026-10-14. Parent: #13/#15/#16, [ADR-0002](adr-0002-isolated-connector-comparison.md) and [ADR-0003](adr-0003-research-advisory-refresh.md).

The current registered-module experiment measures connector APIs inside a standard-library proxy. It cannot establish Caddy server defaults, TLS authority enforcement, real reverse-proxy backend verification or configuration replacement. Extend the isolated module with an owned configured Caddy server, retaining the original forty wire/twenty-two pool observations unchanged.

Register only Caddy's reverse-proxy and filesystem-storage packages in addition to existing imports. Its HTTP transport adds github.com/pires/go-proxyproto v0.12.0 to the loaded graph; that version was already selected by Caddy. Review its checksum-database identities, VCS origin and Apache-2.0 LICENSE before import, preserve its notice in private exports, and refresh the complete loaded graph inventory. No existing version changes, standard-module aggregate or upstream patches. The [inventory](../../research/coraza/connector-dependencies.json) remains a private unmodified research review, not redistribution approval.

Run the full configuration in a child of the test executable, with owned XDG config/data directories set before package initialization. Disable the admin endpoint, config persistence, automatic HTTPS/ACME/redirects and all protocols except HTTP/1.1. Use ephemeral loopback listeners, explicit timeouts, synthetic .test host routes, an ephemeral CA/leaf key and explicit verified backend roots/name. No TLS verification bypass, public listener, installed service or external backend. Erase owned assets and prove listener absence after Caddy Stop and child exit; retain only synthetic typed receipts and hashes in Git.

Compare a baseline with strict_sni_host=false to the existing relayd companion's app.test SNI with app.test/api.test HTTP authorities. Then explicitly enable strict_sni_host and measure matched and mismatched authorities. The companion receives PROXY v1 addresses without SNI; its existing api-get observation intentionally uses app.test SNI. Do not infer authority binding or local-sender authentication from either baseline. Strict Caddy configuration is a measured alternative, not automatic policy selection for Aegvium.

Use Caddy's actual TLS/server/router/WAF/reverse-proxy/error rendering and Load replacement/Stop APIs. Synthetic backends independently record receipts and bytes, including response-denial effects. Include hostile/oversized requests, metadata removal, invalid replacement preserving known-good forwarding, route activation/removal/rollback, backend name/CA/cleartext failures and recovery. Keep configuration-level explicit body/header policies separate from connector defaults. Full protocol/streaming/resource/soak/rule-distribution and image lineage remain open.

The [scoped packet](../milestones/M1/CONFIGURED-CADDY.md) requires host/advisory and owned native evidence in this same PR, including an offline native compile of the extended fixture. It supersedes ADR-0002's API-only scope solely for this experiment. CEL and deprecated unimported OpenPGP advisory residuals remain unchanged adoption blockers. Rollback removes this optional fixture/controller mode/import and restores its module/inventory delta while preserving all historical observations. No runtime service or installer is changed.
