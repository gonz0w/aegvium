# ADR 0009: host-only stock release verification

Status: bounded research tooling decision, 2026-10-18; no installed runtime dependency. Supports OB-01–04 and #12/#14 within authorized provenance research.

Use the existing, unmodified signify-osx 1.4 host build solely to authenticate OpenBSD stock release inputs. Source commit `9a654d698f5dc957ac407a3156a638bb3b77add2`, archive SHA-256 `5aa954fe6c54f2fc939771779e5bb64298e46d0a4ae3d08637df44c7ed8d2897`, exact Darwin arm64 executable SHA-256 `4b9b2069c5e5acda9d35ca898ecd5afc050094170cf3c73fa7cf9eb615530946`. Require the exact executable identity before invoking it; no moving refs, global install, source refresh, signing or verifier code changes.

The sibling BootWeave review records the build, adapted upstream checks and exact binary; Aegvium independently rehashes the actual input and performs its own release verification. Earlier sibling results remain references, not Aegvium test evidence. The pinned source Makefile/README and ISC port LICENSE were read; upstream files retain their individual notices. Local-only use does not complete source/binary redistribution review. Neither tool nor its bundled source enters Git, a payload or media. The port's no-op pledge shim supplies no OpenBSD confinement evidence. Removal means deleting the owned ignored tool copy and returning to base-signify-only verification.

Trust bootstrap explicitly relies on official OpenBSD HTTPS publishing plus the host TLS trust infrastructure. The 7.9 base public key record on the [official release page](https://www.openbsd.org/79.html) is `RWTSdNN9A3yvWNn7mUjXwv9DOCOUnyfuV+mq1iGPIfD+NhN8EYnEQ1at`; the [official key file](https://ftp.openbsd.org/pub/OpenBSD/7.9/openbsd-79-base.pub) has SHA-256 `b7ee8e7981549a1f707a4ed05115a99959a5f9e34b9bed9f9a098be17dd7e4b1`. Matching official endpoints is not an independent organizational or out-of-band trust root. A changed key/tool/artifact refuses; it needs a separate reviewed pin update. No custom cryptographic implementation or digest-only authentication substitute is introduced.

The [official FAQ](https://www.openbsd.org/faq/faq4.html#Download) describes explicit-key signify verification of stock images and the authenticated-ISO missing-list distinction. This ADR does not itself qualify native compatibility, original firmware/host trust, a new installer, deployment or a WAF. Runtime dependencies and broader distribution remain separate decisions. Affected WAF/traffic/security/advisory validation stays paused; ordinary release-input verification is separate work, not a retry of that validation.
